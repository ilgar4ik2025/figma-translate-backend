# Документ требований

## Введение

Данная спецификация определяет требования для добавления второй вкладки в существующий Figma-плагин "App Store Screenshot Translator PRO". Новая вкладка "Screenshot Generator" позволит пользователям генерировать профессиональные скриншоты для App Store с нуля, используя AI, создавая полный рабочий процесс, где Вкладка 2 генерирует скриншоты, а Вкладка 1 их локализует.

## Глоссарий

- **Плагин**: Figma-плагин "App Store Screenshot Translator PRO"
- **Вкладка_1**: Существующая вкладка "Screenshot Localizer" для локализации скриншотов
- **Вкладка_2**: Новая вкладка "Screenshot Generator" для создания скриншотов с нуля
- **Окно_UI**: Единое окно плагина, содержащее обе вкладки
- **Слайд**: Одна композиция скриншота для App Store (фон + текст + мокап)
- **Структура_Истории**: Последовательность из 5 слайдов, сгенерированная AI
- **CometAPI**: API-сервис, предоставляющий доступ к моделям GPT и Gemini
- **Сервис_GPT**: Модель chatgpt-4o-latest для текстов и сторителлинга
- **Сервис_Gemini**: Модель Gemini 2.5 Pro для генерации визуальных фонов
- **Описание_Приложения**: Информация от пользователя о категории, аудитории и стиле приложения
- **Мокап**: Рамка iPhone в портретной ориентации, содержащая скриншот пользователя
- **Фон**: Сгенерированная AI визуальная атмосфера для каждого слайда
- **Заголовок**: Основной текст на каждом слайде
- **Подзаголовок**: Вторичный описательный текст на каждом слайде

## Требования

### Требование 1: Архитектура на основе вкладок

**Пользовательская история:** Как разработчик плагина, я хочу поддерживать единое окно плагина с несколькими вкладками, чтобы пользователи имели унифицированный опыт без управления отдельными плагинами.

#### Критерии приемки

1. Плагин ДОЛЖЕН содержать ровно две вкладки в одном Окне_UI
2. КОГДА Плагин загружается, Окно_UI ДОЛЖНО отображать Вкладку_1 и Вкладку_2 как выбираемые опции
3. КОГДА пользователь переключает вкладки, Плагин ДОЛЖЕН сохранять состояние неактивной вкладки
4. Плагин ДОЛЖЕН поддерживать всю существующую функциональность Вкладки_1 без изменений
5. КОГДА Вкладка_2 активна, Плагин ДОЛЖЕН отображать интерфейс Screenshot Generator

### Требование 2: Сбор пользовательского ввода

**Пользовательская история:** Как пользователь, я хочу описать назначение и стиль моего приложения, чтобы AI мог сгенерировать релевантные скриншоты.

#### Критерии приемки

1. КОГДА отображается Вкладка_2, Плагин ДОЛЖЕН предоставить поля ввода для категории приложения, целевой аудитории и стилевых предпочтений
2. КОГДА пользователь предоставляет Описание_Приложения, Плагин ДОЛЖЕН валидировать, что обязательные поля не пусты
3. ГДЕ пользователь хочет включить реальные скриншоты, Плагин ДОЛЖЕН предоставить интерфейс загрузки изображений скриншотов
4. КОГДА пользователь загружает скриншоты, Плагин ДОЛЖЕН валидировать, что изображения в поддерживаемых форматах
5. Плагин ДОЛЖЕН позволять пользователям продолжить с загруженными скриншотами или без них

### Требование 3: Генерация структуры истории с помощью AI

**Пользовательская история:** Как пользователь, я хочу, чтобы AI создал связную историю из 5 слайдов для моего приложения, чтобы мои скриншоты рассказывали убедительную историю.

#### Критерии приемки

1. КОГДА пользователь отправляет Описание_Приложения, Плагин ДОЛЖЕН отправить описание в Сервис_GPT
2. Сервис_GPT ДОЛЖЕН сгенерировать Структуру_Истории, содержащую ровно 5 слайдов
3. КОГДА генерируется Структура_Истории, Сервис_GPT ДОЛЖЕН создать Заголовок и Подзаголовок для каждого слайда
4. Сервис_GPT ДОЛЖЕН обеспечить, чтобы Структура_Истории следовала лучшим практикам маркетинга App Store
5. КОГДА генерация Структуры_Истории завершается, Плагин ДОЛЖЕН отобразить структуру пользователю для проверки

### Требование 4: Генерация фоновых изображений

**Пользовательская история:** Как пользователь, я хочу сгенерированные AI фоны, соответствующие эстетике App Store, чтобы мои скриншоты выглядели профессионально.

#### Критерии приемки

1. КОГДА Структура_Истории одобрена, Плагин ДОЛЖЕН отправить описание каждого слайда в Сервис_Gemini
2. Сервис_Gemini ДОЛЖЕН сгенерировать Фон для каждого из 5 слайдов
3. КОГДА генерируются фоны, Сервис_Gemini ДОЛЖЕН следовать визуальным руководствам App Store
4. Плагин ДОЛЖЕН обеспечить, чтобы все Фоны были в формате портретной ориентации iPhone
5. КОГДА генерация фона не удается для любого слайда, Плагин ДОЛЖЕН повторить попытку до 3 раз перед сообщением об ошибке

### Требование 5: Композиция слайдов

**Пользовательская история:** Как пользователь, я хочу, чтобы каждый слайд объединял фон, текст и элементы мокапа, чтобы у меня были полные скриншоты для App Store.

#### Критерии приемки

1. КОГДА все фоны сгенерированы, Плагин ДОЛЖЕН создать 5 композиций Слайдов в Figma
2. Плагин ДОЛЖЕН позиционировать Заголовок и Подзаголовок на каждом Слайде согласно конвенциям макета App Store
3. ГДЕ пользователь загрузил скриншоты, Плагин ДОЛЖЕН вставить соответствующий скриншот в каждый Мокап с правильным масштабированием
4. Плагин ДОЛЖЕН обеспечить, чтобы весь текст был читаемым на Фоне
5. КОГДА композиция завершена, Плагин ДОЛЖЕН организовать все 5 слайдов во фрейме Figma

### Требование 6: Интеграция с CometAPI

**Пользовательская история:** Как разработчик, я хочу использовать CometAPI для обоих AI-сервисов, чтобы иметь унифицированную интеграцию API.

#### Критерии приемки

1. Плагин ДОЛЖЕН взаимодействовать с Сервисом_GPT через эндпоинты CometAPI
2. Плагин ДОЛЖЕН взаимодействовать с Сервисом_Gemini через эндпоинты CometAPI
3. КОГДА выполняются API-запросы, Плагин ДОЛЖЕН включать правильные учетные данные для аутентификации
4. КОГДА API-запросы не удаются, Плагин ДОЛЖЕН возвращать описательные сообщения об ошибках пользователю
5. Плагин ДОЛЖЕН корректно обрабатывать ограничение скорости API с экспоненциальной задержкой

### Требование 7: Эндпоинты Backend API

**Пользовательская история:** Как разработчик, я хочу использовать serverless-функции для обработки AI-запросов, чтобы API-ключи оставались защищенными.

#### Критерии приемки

1. Плагин ДОЛЖЕН создать новую Vercel serverless-функцию для генерации скриншотов
2. Serverless-функция ДОЛЖНА принимать Описание_Приложения и возвращать Структуру_Истории
3. Serverless-функция ДОЛЖНА принимать описания слайдов и возвращать Фоновые изображения
4. КОГДА обрабатываются запросы, serverless-функция ДОЛЖНА валидировать входные параметры
5. Serverless-функция ДОЛЖНА следовать той же архитектурной схеме, что и существующий эндпоинт translate.js

### Требование 8: Формат вывода

**Пользовательская история:** Как пользователь, я хочу, чтобы все сгенерированные скриншоты были в портретном формате iPhone, чтобы они были готовы для отправки в App Store.

#### Критерии приемки

1. Плагин ДОЛЖЕН генерировать ровно 5 слайдов на каждый запрос генерации
2. Плагин ДОЛЖЕН обеспечить, чтобы все слайды были в размерах портретной ориентации iPhone
3. КОГДА создаются фреймы Мокапа, Плагин ДОЛЖЕН использовать стандартное соотношение сторон портретной ориентации iPhone
4. Плагин ДОЛЖЕН обеспечить, чтобы Фоновые изображения соответствовали размерам портретной ориентации iPhone
5. КОГДА генерация завершается, Плагин ДОЛЖЕН экспортировать слайды в формате, совместимом с локализацией Вкладки_1

### Требование 9: Контроль пользователя и совместное творчество

**Пользовательская история:** Как пользователь, я хочу контролировать творческое направление, пока AI занимается исполнением, чтобы результаты соответствовали моему видению.

#### Критерии приемки

1. КОГДА описывается приложение, Плагин ДОЛЖЕН позволять пользователям детально указывать стилевые предпочтения
2. Плагин ДОЛЖЕН позволять пользователям регенерировать отдельные слайды без регенерации всех 5
3. КОГДА Структура_Истории сгенерирована, Плагин ДОЛЖЕН позволять пользователям редактировать текст Заголовка и Подзаголовка перед финальной композицией
4. Плагин ДОЛЖЕН позволять пользователям изменять порядок слайдов в Структуре_Истории
5. ГДЕ пользователи не удовлетворены фонами, Плагин ДОЛЖЕН предоставить опцию регенерации для отдельных слайдов

### Требование 10: Интеграция с существующей локализацией

**Пользовательская история:** Как пользователь, я хочу, чтобы сгенерированные скриншоты бесшовно работали с вкладкой локализации, чтобы я мог создавать многоязычные ресурсы для App Store.

#### Критерии приемки

1. КОГДА Вкладка_2 генерирует слайды, Плагин ДОЛЖЕН создавать элементы Figma, совместимые с обработкой Вкладки_1
2. Плагин ДОЛЖЕН обеспечить, чтобы сгенерированные текстовые элементы были выбираемыми для локализации Вкладки_1
3. КОГДА пользователь переключается с Вкладки_2 на Вкладку_1, Плагин ДОЛЖЕН сохранять сгенерированные слайды в рабочем пространстве
4. Плагин ДОЛЖЕН обеспечить, чтобы элементы Мокапа сохранялись во время локализации
5. Плагин ДОЛЖЕН документировать рабочий процесс от Вкладки_2 к Вкладке_1 для пользователей

### Требование 11: Обработка ошибок и обратная связь с пользователем

**Пользовательская история:** Как пользователь, я хочу получать четкую обратную связь во время генерации, чтобы понимать, что происходит, и иметь возможность устранять проблемы.

#### Критерии приемки

1. КОГДА генерация выполняется, Плагин ДОЛЖЕН отображать индикаторы прогресса для каждого этапа
2. КОГДА возникают ошибки API, Плагин ДОЛЖЕН отображать понятные пользователю сообщения об ошибках
3. ЕСЛИ генерация не удается, Плагин ДОЛЖЕН сохранять пользовательский ввод для повторных попыток
4. Плагин ДОЛЖЕН отображать оценочное оставшееся время во время генерации фонов
5. КОГДА генерация успешно завершается, Плагин ДОЛЖЕН уведомить пользователя и отобразить результаты

### Требование 12: Производительность и управление ресурсами

**Пользовательская история:** Как пользователь, я хочу, чтобы генерация скриншотов завершалась за разумное время, чтобы я мог быстро итерировать.

#### Критерии приемки

1. КОГДА генерируется Структура_Истории, Плагин ДОЛЖЕН завершить работу в течение 30 секунд
2. КОГДА генерируются фоны, Плагин ДОЛЖЕН обрабатывать слайды параллельно, где это возможно
3. Плагин ДОЛЖЕН ограничивать использование памяти, чтобы предотвратить деградацию производительности Figma
4. КОГДА генерируются большие изображения, Плагин ДОЛЖЕН оптимизировать их для холста Figma
5. Плагин ДОЛЖЕН кэшировать сгенерированный контент, чтобы избежать избыточных API-вызовов во время редактирования
